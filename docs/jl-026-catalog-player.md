# JL 0.9.26 desktop catalog/player repair

This work targets the Harbor Windows application at base `33702fbe584e86eaac6758727bb1170271f9c0ce`. It does not count the separately hosted Watch frontend as desktop implementation. No provider playback, provider downloads, account changes or production publication were performed.

## Actual paths and acceptance

| Requested behavior                      | Desktop source and result                                                                                                                                                                                                                                                                                              |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Movies/Shows not silently missing       | `iptv/xtream-vod.ts` now keeps catalog data when optional category labels fail, bounds that optional request, and treats error-shaped catalogs as failures rather than caching an empty success. Existing cached data/retry UI remains available.                                                                      |
| Preserve variants and provider identity | `iptv/vod.ts` deduplicates movies by provider ID rather than title/year; language and edition variants remain selectable. Unicode series names no longer all normalize to an empty identity. Original playlist/addon configurations are untouched.                                                                     |
| Correct episode/season mapping          | Explicit provider episode IDs and number fields survive into playback. Season zero stays zero. Missing numbers are labelled unnumbered rather than invented from URL order. Source edits invalidate in-memory episode cache identity; valid cache entries expire after five minutes. Malformed replies are not cached. |
| Retry and navigation                    | Playlist episode requests receive an abort signal; changing tab/source/detail or leaving cancels the request. Late results are discarded. Failed requests show Retry, and true empty responses have a distinct message.                                                                                                |
| Search and metadata                     | Playlist search tolerates punctuation, word order and Latin accents while keeping non-Latin marks. TMDB artwork/metadata requires a unique exact normalized title and, when supplied, matching year; ambiguous results leave provider data intact.                                                                     |
| English/US preference                   | VOD ordering uses existing region and preferred-language settings and existing group relevance scoring. All foreign and unlabelled items remain; labels do not establish actual audio language.                                                                                                                        |
| Addon compatibility/search              | Fused search recognizes mixed-case Movie/Series manifests while retaining exact protocol type case, safely encodes catalog path segments, separates movie/show IDs, and bounds stalled body reads. No addon manifest/configuration is removed.                                                                         |
| Signed URL playback                     | M3U request headers now survive VOD selection just as they already did for Live TV. HTML fallback classifies explicit file paths before legacy playlist hints, ignores unrelated query tokens, and does not treat browser compatibility flags as live status. The normal Windows mpv engine remains the media parser.  |
| Native timeout                          | `stream_proxy.rs` applies a 30-second asynchronous deadline to response headers, including redirects. The deadline ends once headers arrive, so it cannot terminate a long media body at 30 seconds. Existing header/redirect and Range policies remain.                                                               |

## Verification and limits

Synthetic provider responses and media paths are used throughout. The focused Node suite covers 59 tests including existing playback redirect, transport preference, first-frame readiness and stalled/paused-player regressions. Two native loopback tests were added: stalled header timeout and a 206 body that continues after the header deadline. Cargo is absent on The Lab, so those Rust tests and the native build require CI verification.

`pnpm run typecheck` passed during validation. `pnpm exec vite build` passed, with the repository's existing mixed static/dynamic import and large-chunk warnings. Final integration must repeat TypeScript and native checks on the combined release branch.

Repository `pnpm run check` cannot run because its `vp` executable is absent. `cargo check` and the required Linux binary build cannot run because Cargo is absent. No replacement lint tool was installed and no successful native-build claim is made.

The user's exact failing title/season/provider example is still pending. These are source-confirmed defects and fixture-tested repairs, not a claim that a real provider mismatch or buffering issue was reproduced. Network/CDN behavior and codecs still require explicitly authorized runtime validation. Opaque media types that cannot be inferred remain the native player's responsibility.

The main Movies and Shows discovery hubs use TMDB/Cinemeta and addon rows; the provider playlist library is a separate existing VOD view. This change repairs that view and shared addon search without silently replacing discovery or routing users to the Watch website. Existing global library/history records remain untouched. Previously colliding non-Latin M3U series now receive distinct IDs; ambiguous historical progress cannot safely be assigned to one of those shows automatically. Xtream series keep their original provider-derived IDs.

This branch is a local integration candidate, not an installer release. The parent release branch must combine account/profile, identity, Offline Room and Sports Hub work, rerun integration checks, compile/test the native changes, and produce the final 0.9.26 installer.
